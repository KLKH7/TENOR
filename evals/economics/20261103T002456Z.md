## Assumptions

- **measured**: ingest tokens per meeting: mean over completed meetings in each build's progress.jsonl (Northwind-XL, synthetic; real meetings may be longer, see FIDELITY.md)
- **measured**: per-question answer tokens, latency and accuracy: the eval report given
- **measured**: ingest model of each build: inferred by re-pricing its tokens with every model in PRICING and keeping the closest match to the recorded cost
- **assumed**: write-time systems with no report rows use their planning estimate (PLANNING_ANSWER_TOKENS) for the answer call
- **assumed**: query-time systems need no LLM at ingest; embedding/indexing cost is ignored for every system (local embedder, ~0 marginal cost)
- **assumed**: ingest can always use the Batch API (it is asynchronous); interactive answers cannot, unless --batch-queries
- **assumed**: prompt-cache override applies one hit rate to all prompt tokens; cache writes are then ignored (writes cost 1.25x but happen once per prefix)
- **guess**: meetings and questions per user per month (CLI defaults 40 and 30): set them
- **ignored**: storage, vector DB hosting, re-ingest on edits, retries, failed calls, the judge (an eval artefact, not a product cost)
